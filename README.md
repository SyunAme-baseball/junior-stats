# ジュニアスタッツ（ジュニスタ）

少年野球のスコアブック＆成績集計アプリ（旧名「野球みえるスコア」）。学年別のチーム分けや球数制限に対応し、集計した成績は卒団時の表彰にも使えます。記号ではなく、プレーが日本語で見えるスコアブックです。少年野球の試合を、保護者がスマホで日本語のボタンを押すだけで記録できる Web アプリです。

## 起動方法

Node.js 20 以上が必要です。

```bash
npm install
npm run dev        # http://localhost:5173 で開く（同じWi-Fiのスマホからは表示される Network のURL）
npm test           # ルールエンジンの単体テスト
npm run build      # 本番用ビルド（dist/）
```

## 動作確認の手順

1. 「試合開始」を押す（サンプルのチーム・打順が入っています）
2. 「ヒット」→「シングルヒット」→「記録する」：一塁にランナーが出て、次のバッターに進む
3. 「四球」→「記録する」：一塁ランナーが押し出されて二塁へ
4. 「ヒット」→「ホームラン」：3点入り、打点3が付く
5. 「三振」を3回：3アウトで自動的に1回裏へ（ランナーは消え、相手の1番から）
6. 「試合経過」から途中のプレーを押して削除・修正：得点・アウト・打順・成績がすべて計算し直される
7. ページを再読み込みしても同じ状況に戻る
8. 「途中経過 →」で結果画面（イニング別得点・選手の活躍・打撃成績・試合経過）

## 設計

- **プレー履歴が唯一の正本**：`Game.plays` だけを保存し、得点・走者・アウト・打順・個人成績は毎回 `replay()` で再計算する。取り消し・途中の修正をしても必ず整合する。
- **打球の種類と走者の結果を分けて記録**：各プレーは「結果の種類」＋「打者・各走者がどこへ行ったか（`moves`）」。種類ごとに“よくある結果”を初期値として出し、確認画面で直せる。
- **確認画面は同じエンジンでプレビュー**：記録前に「アウト 1→2 / 得点 1点 / 打点 1」を表示。矛盾（同じ塁に2人など）は記録できない。
- **保存層は UI から分離**：`GameRepository` インターフェース。今は `LocalStorageRepository`。クラウド同期は同じインターフェースの実装を差し替える。
- チーム・選手は固定IDで管理（チーム名を変えても集計がずれない）。

```
src/
├── domain/            野球のルールとデータ（UIに依存しない）
│   ├── types.ts         データモデル
│   ├── results.ts       プレー種別の定義と、走者の動きの初期値
│   ├── engine.ts        replay()：プレー履歴→試合状況・成績
│   ├── describe.ts      プレーを日本語の文章にする
│   └── engine.test.ts   テスト
├── storage/           保存層（repository.ts がインターフェース）
└── ui/                画面（試合一覧・試合作成・スコアボード・プレー確認・結果）
```

## 打球の入力（結果 → 方向）

- 試合画面の「ヒット」「ゴロ」「フライ」「ライナー」を押すと、ポップアップで順に選びます。
  1. 結果：ヒットなら塁打数（単打・二塁打・三塁打・本塁打・内野安打）。ゴロはアウト・併殺・犠打・野手選択・エラー、フライはアウト・犠牲フライ・エラー、ライナーはアウト・併殺・エラー（その場面でありえないものは押せません）。
  2. 打球の方向：グラウンドの図（外野はレフト線・レフト・左中間・センター・右中間・ライト・ライト線、内野はサード・ショート・セカンド・ファースト・ピッチャー・キャッチャーの13か所。三遊間などを抜けた打球は「レフト前」などの外野で記録します）をタップすると、そのまま走者の確認画面に進みます。ヒットなどは「方向なしで進む」も選べます。アウトは捕った守備位置を決めるため方向が必要です（ショートの位置のゴロ→ショートゴロ、ライト線のフライ→ライトフライ、内野のフライ→「セカンドフライ」など）。
- 試合経過には「左中間への二塁打」「レフト前ヒット」「ショートライナー」のように表示されます。確認画面でも結果と方向を選び直せます。以前の版のレフト・センター・ライトの記録もそのまま読めます。
- エラー・野手選択では、確認画面の「守備の流れ」に ①打球の種類 ②打球を捕った人 ③送球した塁 ④エラーした人 ⑤エラーの種類（打球を捕れなかった／悪送球／送球を捕れなかった）を記録できます（すべて任意）。ゴロなどから入力すると①②は自動で入ります。試合経過には「セカンドゴロ、本塁へ送球、キャッチャーが送球を捕れずエラーで出塁」のように表示されます。
- ワンヒットワンエラー：ヒットの確認画面で「ヒットのあとにエラーがあった」にチェックし、送球した塁・エラーした人・エラーの種類を選びます（方向の外野手・悪送球・バッターを1つ先の塁が初期値）。安打は単打のまま、相手の失策に1つ数え、試合経過は「ライト前ヒット、二塁へ送球、ライトが悪送球」と表示されます。
- 一覧から選びたいときは「ヒット（一覧）」「その他のアウト」などのボタンを使います。
- 確認画面を開くと、打者・走者の動きを1人ずつポップアップで聞きます。順番はバッター → 3塁 → 2塁 → 1塁ランナーです。ベースの図をタップすると、次の人のポップアップに切り替わります。ランナーは元の塁（点線）をタップすると「そのまま」、アウトは「アウト（タッチ等）」「フォースアウト」のボタンです。よくある動きは最初から入っているので、そのままでよければ「このまま」を押します。全員終わると確認画面に全員の行き先が並び、名前を押すとその人のポップアップを開き直せます。ランナーがいない三振・四球・アウトなど、行き先が決まっている場合はポップアップを出しません。
- 確認画面で、後ろの走者（バッターを含む）が前の走者より先の塁に進む設定（例：一塁走者「そのまま」でバッターが二塁）はエラーになり、記録できません。アウトになった走者は追い越しの対象外です。

## 投手の指標

- 試合結果とチーム画面の投手成績に、K/BB（奪三振÷与四球）・ストライク率（ストライク÷球数。ファウル・打球を含む）・WHIP（(与四球＋被安打)÷投球回。死球は含めない）を表示します。
- チーム画面の「投手の指標」で、投手ごとの3つの指標を横棒グラフで比べられます（参考線：WHIP 1.30、K/BB 2.00、ストライク率 60%）。
- ストライク率は、球数が対戦打者数の2倍に満たない（1球ごとの入力をほとんどしていない）ときは「—」になります。四球0の投手の K/BB は「三振数/0」と表示します。

## チーム名簿・カテゴリー・シーズン成績

- トップ画面の「＋ チームを作る」で、チーム名簿（選手の名前と学年）を1つ登録します。背番号は名簿に入れません。
- 試合作成でカテゴリー（6年生・5年生・4年生・3年生以下・全学年）を選ぶと、その学年の選手だけが選べます。「下の学年の選手も選べるようにする」で下級生も出せます。
- 背番号は試合ごとに入力します（前回の番号が初期値）。先発は「選手・背番号・守備位置」、控えは背番号だけを入れ、背番号を入れた控え選手だけがその試合の代打・代走・守備交代の候補になります。背番号や選手の重複はエラーになります。
- 打順はカテゴリーごとに前回のものが初期値になります。
- チーム画面で、シーズン（試合で入力）とカテゴリーで絞り込んだ勝敗・勝率、試合一覧、打撃・投手成績の通算が見られます。
- 新年度は「新年度：全員の学年を1つ上げる」を押します（6年生は「卒団」になり、選手選びに出なくなります。過去の成績は残ります）。
- 以前の版の「シーズン×学年ごとのチーム」は、そのまま1チームとして読み込み、チームの学年を選手の学年に移します。
- 「全データを書き出す」でチームと全試合を1ファイルにバックアップし、「ファイルから読み込む」で戻せます。

## 1球ごとの入力と球数制限

- 試合中は画面の下に「ボール・見逃し・空振り・ファウル・↶（取り消し）」のボタンが常に出ます。
- ボタンの上に、いまの投手の今日の球数（大きな数字）・制限までの残り・進み具合のバーが出ます。制限の10球前で黄色、到達で赤になります。
- 「ファウル」を押すと「ファウル（打ち直し）」「捕られてアウト（捕った人を選ぶ＝ファウルフライ）」を選ぶ画面が出ます。2ストライクのときは「ファウルチップを捕手が捕った」「スリーバント失敗」（どちらも三振）も選べます。
- 4つ目のボールは四球、3つ目のストライクは三振の確認画面が自動で開きます。打った球・死球も1球として数えます。
- 投手の球数は「今日の合計」（同じ日の別の試合も合算）で表示し、制限の10球前から注意、制限に達したら警告を出します。制限は試合作成で設定（初期値70球）。
- 1球ごとの入力をしない場合、球数は「打席数」程度にしかならない点に注意してください。

## 1ファイル版（デモ・配布用）

`npm run build:single` で、JS・CSS を埋め込んだ `dist/mieru-score.html` を作れます。サーバーなしでも、このファイルを開くだけで動きます。

## 名簿とチーム

- **名簿**（ホームの「名簿」）：クラブの選手を1か所で管理します。名前と学年で追加し、名前の変更・学年の変更・退団（成績は残る）・復帰・削除（入力ミス用）ができます。「全員の学年を1つ上げる」で進学（6年生は卒団）。
- **チームを作る**：チーム名と学年（例：4年生）を選ぶと、名簿から今いる4年生以下の選手が並びます（最初は全員チェック済み、「4年生だけ」も1タップ）。チェックした選手でチームができます。
- 選手の名前・学年はいつも名簿のものを使うので、名簿で進学させると全チームに反映されます。進学後はチーム画面の「メンバーを選び直す」で新しく入る学年の選手を加えます。
- 名簿で選手を追加するとき、学年がいちばん近いチームにもそのまま入れられます。
- 試合を作るときのカテゴリーは、チームの学年（4年生以下のチーム→「4年生」）が最初に選ばれます。
- 以前の版のデータは、各チームの選手から名簿を自動で作ります。全データのバックアップには名簿も入ります。

## ホーム画面

緑のグラウンドとダイヤモンドを背景にしたヘッダーと、オレンジの「＋ 新しい試合をつける」ボタン。チームカードには選んだシーズンの勝敗・チーム打率・盗塁、最近の試合には勝/負/分（試合中は「途中」）のバッジとスコアを表示します。

## アイコン

RPGのステータス画面をイメージしたイラスト（ボール・星・2本のゲージ）。

- `public/icon.svg`：基本のアイコン（マニフェスト用）

- `public/icon-maskable-512.png`：Android で丸や角丸に切り抜かれても欠けないよう、余白を広くとった版
- `public/apple-touch-icon.png`（180px）：iPhone の「ホーム画面に追加」用

## 公開（GitHub Pages・無料）

- `.github/workflows/pages.yml`：main に送るたびに `npm test` → `npm run build` → GitHub Pages に公開。
- 最初の1回だけ、リポジトリの Settings → Pages → Source を「GitHub Actions」にする。
- `vite.config.ts` は `base: "./"` なので、`https://ユーザー名.github.io/リポジトリ名/` のようなサブフォルダでも動く。
- データは各自の端末（ブラウザ）に保存されるため、公開URLは途中で変えない（変えると前のデータが見えなくなる。バックアップの書き出し→読み込みで移せる）。

## スマホアプリとして使う（ホーム画面に追加）

`npm run build` した `dist/` を HTTPS のサーバー（GitHub Pages・Netlify・Cloudflare Pages など無料のもので可）に置き、スマホで開いて「ホーム画面に追加」すると、アプリのように全画面で起動し、電波がなくても開けます。

## 端末間の共有

- 試合画面の「共有」、またはチーム画面の「チームの名簿と全試合を共有」から、リンク（LINEなどに貼れる）またはファイルで送れます。
- 受け取った人がリンクを開くと「データを取り込む」画面が出て、どの登録チームの成績に入れるかを選べます。別々に作ったチームでも、選手を名前で対応させて合算できます。
- 同じ試合を両方の端末で持っている場合は、更新日時が新しい方を残します。
- 注意：リンクは自分のサーバーに置いたアプリのURLで作られます。`npm run dev` のまま（localhost）では他の人の端末では開けません。

## 実装済みのルール

- 3アウトで攻守交代、走者リセット、打順は攻守交代をまたいで継続（一巡で1番へ）
- 四球・死球の押し出し（フォースされた走者だけが進む）
- 犠牲フライ・犠打（打数に数えない。2アウトからは不成立として打数に数える）
- 併殺（打点なし）
- 第3アウトと得点：第3アウトが「打者の一塁到達前のアウト」または「フォースアウト」なら得点にしない。それ以外（タッチプレー）は「先にホームを踏んだか」を確認画面で選ぶ
- エラー出塁は安打・打点にせず、守備側の失策に数える
- 盗塁・暴投・捕逸・ボーク・盗塁死・走塁死（打席に数えず、打順も進めない）
- 守備位置：試合作成で打者ごとに設定（「守備なし」も可）。同じ位置に2人は登録できない
- 代打・代走（打順の枠を引き継ぐ。代走の得点は代走の選手に付く。守備位置は「なし」になり、守備につくときに画面が設定を促す）
- 守備交代・ピッチャー交代・守備位置の変更（1つの画面で、複数人の入れ替えをまとめて記録）
- エラーで出塁したときは、エラーした守備位置を記録できる
- 投手成績：投球回・対戦打者・被安打・被本塁打・奪三振・与四球・与死球・失点。そのとき守っていたピッチャーに自動で付く。失点はその投手が出した走者がかえった数
- 勝利投手・敗戦投手：勝ったチームが最後にリードを奪ったときの投手が勝ち、その得点の走者を出した投手が負け。先発が規定の回（7回以上の試合は5回、それ未満は予定回数の6割）に満たなければ、最も長く投げた救援投手が勝ち。結果画面で手動変更できる
- 盗塁・盗塁死・牽制死：走者ごとに記録し、試合経過・主な出来事・打撃成績・シーズン通算に表示。牽制でのアウトは投手の「牽制刺」にも数える
- 試合終了の自動判定：最終回表終了でホームがリード（裏はX）、サヨナラ（本塁打以外は勝ち越しに必要な点数まで）、同点なら延長
- コールド・時間切れは手動で「試合を終了する」
- 打点は自動計算し、手動で上書き可能
- 迷ったプレーは「あとで確認する」で印を付けられ、結果画面に件数を表示

## 未対応・簡略化しているルール（今後の改善）

| 項目 | 現状 |
|---|---|
| 自責点・防御率 | 未対応（失点のみ） |
| 勝利投手の「最も効果的な救援投手」の判断 | 最も多くアウトを取った救援投手で代用。違う場合は手動で変更 |
| セーブ・ホールド、球数 | 未対応 |
| 走者が野選で入れ替わったときの失点責任 | 未対応（最初に塁に出た打者を出した投手の責任のまま） |
| 複数端末での同時入力（リアルタイム同期） | 未対応。サーバー（Firebase など）の準備が必要。今はリンク／ファイルで共有して取り込む |
| 1球ごとの記録の修正 | 「↶」で直前の1球を取り消すのみ（途中の1球だけを直すことはできない） |
| 守備成績（刺殺・補殺）、エラーをした選手の成績 | 未対応（エラーの守備位置は試合経過にだけ表示） |
| 一度退いた選手の再出場の制限 | チェックしない（少年野球のリエントリー規定は大会ごとに異なるため） |
| 打順間違い（打順違反のアピール） | 未対応。違う選手を選んで記録すると、その選手の次の打順へ進むだけ |
| エラーが絡んだ打点・自責点 | 打点はエラー出塁なら0で自動、必要なら手動で修正 |
| 野選・失策による走者の進塁の記録区分 | 走者の進塁は記録するが、進塁理由（失策で何個進んだか）は記録しない |
| タイブレーク（延長の無死一二塁など） | 未対応 |
| コールド時に途中の回を無効にする規定 | 自動判断しない（大会規定による） |
| 振り逃げで一塁が埋まっている場合などの細かい成立条件 | 自動判定しない（確認画面で結果を選ぶ） |
| 打撃妨害・走塁妨害・インフィールドフライ | 未対応（「その他」で走者の動きだけ記録可能） |
| 試合経過の時系列は削除・修正のみ | 途中へのプレー挿入は未対応 |
